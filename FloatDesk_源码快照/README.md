# FloatDesk — Mac 桌面悬浮快捷工作台

常驻 macOS 桌面的悬浮快捷工作台：一个可拖动的光滑圆点，点击展开环形菜单，支持网页 / 应用 / 文件 / 图片 / 快捷键五类项目，多工作场景切换，全局快捷键，本地配置优先、不上云、不采集遥测。

- 平台：macOS（最低 10.15；优先兼容 Intel x64 与 macOS Sequoia，Apple Silicon arm64 亦支持）
- 技术栈：Electron + TypeScript（主进程）/ 原生 HTML+CSS+JS（渲染进程）
- 安全：主进程 `contextIsolation: true`、`nodeIntegration: false`，渲染进程只通过最小化的 `preload` IPC 接口通信；禁止 `eval` 与拼接 shell 命令执行用户输入；URL 仅允许 `http(s)`。

---

## 1. 安装依赖

```bash
cd floatdesk
npm install
```

> 需要本机已安装 Node.js 18+ 与可下载 Electron 的网络环境。`npm install` 会一并安装 Electron 与 electron-builder。

## 2. 开发运行

```bash
npm run start      # 先 tsc 编译，再用 electron 启动（开发模式）
```

等价于：`npm run build && electron .`

## 3. 静态检查与单元测试

```bash
npm run compile    # 仅类型检查（tsc --noEmit）
npm test           # 编译并运行 Node 单元测试（171 项：校验 / 颜色 / 便签 / 便签多标签 / 书签解析 / 图标 / 网页元信息 / 输入法）
npm run smoke      # 真实 Electron 加载设置页 + 悬浮窗 + 便签，脚本化点击跑完增删改链路（165 项断言）
npm run smoke:note # 便签真实链路自检：真 NoteWindow + 真 IPC + 真落盘（7 项断言，不打桩）
npm run smoke:bookmarks  # 浏览器书签批量导入自检（28 项断言）
npm run smoke:notepages  # 便签多标签 / 30 版历史 / 预览后恢复 / 划线自检（39 项断言）
npm run visual     # 截图自检：便签富文本 + 四种圆点配色，产物在 /tmp/fd-visual/
npm run probe      # 联网自检：对真实网站跑 favicon / 标题探测
```

`npm test` 覆盖纯逻辑（`src/shared/*.ts`），不依赖 GUI 与网络；`npm run smoke` 用真实 Chromium 渲染页面，把 IPC 后端换成内存配置，脚本化点击并断言后端配置的最终状态；`npm run smoke:note` 反过来——IPC 与落盘全用真的，专门盯便签这条链路（真实渲染进程 → preload → 主进程 → 磁盘 → 再读回来）。


## 4. 打包为 .dmg（按需执行，不随改动自动打包）

> **约定：日常改动只跑 `npm test` / `npm run smoke` 验证，不自动打包。**
> 需要出包时再明确执行下面的命令；`release/` 里的产物不会随源码改动自动更新。

```bash
# Intel x64（首版交付目标）
npm run pack:intel

# Apple Silicon arm64
npm run pack:arm

# 一步生成 Intel dmg（不发布到商店）
npm run dist
```

产物位于 `release/` 目录下（如 `FloatDesk-1.0.0.dmg`）。

> 公开分发建议用 Apple Developer ID 签名并公证（`codesign` + `notarytool`）；开发版本可在本机直接运行，无需公证。本仓库未内置签名配置，如需公证请补充 `build.mac.identity` 与钥匙串凭证。

## 5. 首次启动与权限

1. 双击 `release/FloatDesk-1.0.0-x64.dmg` 或将 `FloatDesk.app` 拖入「应用程序」。
2. 首次运行若提示「无法验证开发者」，在「系统设置 → 隐私与安全性」中点击「仍要打开」。
3. 悬浮圆点默认出现在主屏右上附近，可拖动到任意位置；点击展开环形菜单，再点圆点或按 `Esc` 收起。
4. **辅助功能权限（仅当使用「向当前应用发送快捷键」时需要）**：
   - 打开「设置 → 快捷键」页，查看权限状态。
   - 未授权时点击「打开系统设置授权」，在「隐私与安全性 → 辅助功能」中勾选 FloatDesk。
   - 该权限仅用于模拟发送组合键（如 Command+C），不采集屏幕或输入内容。
5. 全局快捷键（默认「唤出菜单 ⌥+空格」「切换场景 ⌥+⇧+S」）在所有应用前台均生效；若与系统/其他应用冲突，主程序会提示失败。

### 8.0 「快捷键」类型项目：用 FloatDesk 的按钮代替在别的应用里按物理键

项目类型选「快捷键」→「向当前应用发送组合键」，录一个组合键（如系统截图 `Command+Shift+4`），之后：

- 点悬浮菜单里这个项目，或按它自己的全局热键，**前台应用收到的就是一记真实的组合键**，等于替你把物理按键按了（截图、复制粘贴、切换标签都能用）。
- 发送走原生桥 `native/sendkey.m`（CGEvent → HID 事件流，和物理按键没有区别），支持完整修饰键组合 + 特殊键（F1–F12、方向键、回车退格 Esc 等）。AppleScript 的 `keystroke` 只能发单字符键，所以系统截图这类组合键以前是发不出去的，现在能了。
- 需要「辅助功能」权限（与「向其他应用发送快捷键」是同一个权限，侧栏底部有状态卡片）；拿不到原生桥时自动退回 AppleScript 单字符键兜底。
- **点悬浮球会自动「链接」到当前前台窗口**：点悬浮球/右键圆点的瞬间，FloatDesk 会记下当时最前台的那个应用（比如你正在用的 Safari），之后从悬浮菜单点出来的快捷键就发给这个「链接窗口」，而不是发给被抢了焦点的 FloatDesk 自己。圆点上方的小药丸会显示当前链接到的窗口名（如「↗ Safari」），让你随时知道快捷方式会落到哪个程序。全局热键触发的快捷键仍直接发当前前台应用（那时前台本来就是目标，不需要链接）。
- 圆点动效可在「设置 → 悬浮球 → 圆点动画」切换：脉冲（默认）/ 呼吸 / 能量环 / 无；开启「减少动态效果」时一律关闭。
- 链接窗口提示药丸的**外观是全局统一的**（见 8.16）：淡紫磨砂胶囊 + 纯白粗体字 + 一圈亮边，**与场景无关**——换场景、新建场景长得完全一样，不再跟场景主题色走。可在「设置 → 悬浮球」里微调两处：**提示磨砂**（滑块 10%–100%，越淡越不挡视线）与**提示文字色**（取色器，默认纯白）。拖动滑块即时在悬浮球上预览，松手即保存。
- 链接窗口提示药丸的**显示行为**也可调（都在「设置 → 悬浮球」，改动经配置广播即时生效）：
  - **显示链接窗口提示**（开关，默认开）—— 关掉后圆点上不再出现这条药丸；主进程照旧捕获链接窗口，快捷键照样发对程序，只是不再画出来。
  - **提示停留时长**（下拉：常驻 / 1 / 2 / 3 / 5 / 10 秒后淡出，默认常驻）—— 不想让它一直挡视线就选几秒：出现一会儿自动退场，**展开菜单或切换链接窗口时重新出现**（这两次正是需要看它的时刻）。不足 1 秒按常驻处理，避免「刚出现就消失」。
  - **自动避让没有开关**（按反馈把上一轮的开关去掉了）：药丸永远按真实占位选位——优先贴着圆点（收起态和空隙够时，手感与从前一致），放不下就往上走「菜单圈上方 → 窗口顶部」这一条路线，每个位置再小幅左右横移 ±14px，**绝不甩到窗口另一侧**；全部躲不开才退回默认位置（也在圆点上方）。**只在「上方」避让**是 8.15 改的：各场景环半径不同，一旦允许落到下方，同一个提示换了场景就跑到圆点下面去了。选位纯函数在 `src/shared/linkedApp.ts`（`pickLinkedAppSlot`），单测覆盖；悬浮窗渲染进程是经典脚本不能 import 值，按「双胞胎」约定各存一份。
  - 顺带修了一个老问题：收起态窗口只有 dotSize+56 那么宽，长应用名（如「Visual Studio Code」）会被窗口硬裁掉；现在药丸的 `max-width` 会跟着窗口收紧走省略号，展开态则可用整个窗口宽度。
  - **收起/展开后按真实窗口尺寸重排**：展开→收起时窗口从大尺寸缩回小球尺寸是异步落地的，若只按旧尺寸算坐标，药丸会被窗口裁到只剩右下角一小块「↗」箭头框。现在 `max-width` 先收紧再测量，且窗口 `resize` 事件在收起态也会触发重排（`placeLinkedApp`），等新尺寸真正生效后再摆一次；`scripts/linked-app-check.js` 的 `float:resize` 桩改为真实 `setBounds`（保持窗口中心），并新增「收起后药丸完整在窗口内」回归断言。
- **设置页「显示提示文字」总开关**（设置 → 常规 → 行为，默认开）：关掉后各设置页和弹窗里的灰色说明文字（`.hint`）整体隐藏，界面更清爽，所有控件、按钮、数值读数都不受影响——色值（`#4d82ff` 这类，`.hint.hval`）、滑杆数值（`.tag`）都保留。实现是 body 上的 `hide-hints` 类 + 一条 CSS（`body.hide-hints .hint:not(.hval) { display:none }`），改动即时生效、写进配置，重开设置窗口保持。

### 8.1 添加网址自动读取图标和名称

两种用法，都是「给个网址，剩下自动填」：

1. **一键快速添加**：设置 → **项目库**页检索框，用右下角小按钮切到「添加网址」模式（🔗），粘贴 `github.com` 或 `https://www.apple.com/cn/`，回车或点「读取并添加」→ 直接生成一个网页项目，名称=网站标题、图标=favicon。
2. **编辑弹窗内补全**：新增/编辑项目选「网页」类型后，目标框右侧出现「读取网站图标和名称」按钮；把光标移出目标框也会自动触发一次（仅在名称或图标还空着时，不覆盖你手填的内容）。读取后旁边会显示图标预览。

实现要点（`src/main/WebProbe.ts` + `src/shared/webmeta.ts`）：

- 只接受 `http(s)`；只写域名会自动补 `https://`。
- 标题优先级：`og:title` → `twitter:title` → `<title>` → `og:site_name` → 域名兜底；会解码 `&amp;` 之类的实体并压缩空白。
- 图标优先级：`apple-touch-icon` → `<link rel="icon">` 中 `sizes` 较大的 → `mask-icon`/svg → `/favicon.ico` 兜底；相对路径按页面地址解析，只允许 http(s)。
- 项目列表的名称列会把图标渲染成真实小图（emoji 就显示 emoji，图片路径/网址就显示图片），不会把路径当文字刷出来。
- **图标下载到本地** `~/Library/Application Support/FloatDesk/item-icons/<sha1>.<ext>`，按文件头判断真实格式（png/jpg/gif/webp/ico/svg/bmp），所以断网、网站改版都不会变空白图。
- 防护：9 秒超时、HTML 只读前 1MB、图标最大 1MB、最多试 4 个候选地址；失败不影响保存，只是图标留空。

### 8.2 所有输入框都支持复制 / 粘贴（含右键菜单）

macOS 上 Electron 应用的 `Cmd+C / Cmd+V / Cmd+X / Cmd+A` 依赖**应用菜单里存在带 role 的「编辑」子菜单**——没有它，输入框里按快捷键什么都不会发生（这是 Electron 最常见的坑之一）。本项目的处理：

- 应用菜单补齐「编辑」：撤销 / 重做 / 剪切 / 复制 / 粘贴 / 粘贴并匹配样式 / 删除 / 全选（`src/main/appMenu.ts`，纯数据模板，有单测覆盖）。
- 三个窗口（悬浮窗 / 设置 / 图片预览）统一挂上原生右键菜单（`src/main/ContextMenu.ts`）：
  输入框里右键 → 撤销/重做/剪切/复制/粘贴/全选；
  **输入框以外一律不弹文本菜单**（设置页已全局禁止选中文字，见 8.12；要复制诊断信息用「关于 → 复制诊断信息」按钮）；
  圆点和菜单项上右键 → 仍然是它们自己的业务菜单（不会多弹一个空菜单）。
- CSS 兜底：`input, textarea, select, [contenteditable]` 显式 `user-select: text`，避免外层 `user-select: none` 让输入框里的文字选不中（悬浮窗和设置页的外层都是 none，见 8.12）。

删除保护与一致性：

- 至少保留 1 个场景；删除**默认场景或当前场景**时，默认身份与当前指针会自动转移到剩下的场景（不再像早期版本那样禁止删除默认场景）。
- 删除项目/场景时，其它场景里「全局触发」指向它的项目会被自动清空目标并停用，避免悬空引用。
- 停用（`enabled: false`）的项目保留在配置里，只是不出现在环形菜单——随时可再启用。

### 8.3 圆点渐变：主题色 → 可调叠加色（还原最初那颗蓝紫圆点）

**曾经的缺陷**：`applySceneStyle()` 一直在把 `scene.themeColor` 写进 CSS 变量 `--theme`，但**没有任何一条样式用过这个变量** —— 圆点的渐变是写死的蓝色（`#6ea8ff → #3b82f6 → #7c3aed`），所以改主题色在界面上完全没反应。改完之后圆点能跟主题色走了，但**只剩单色**，丢了最初设计稿那颗「蓝渐变到紫」的层次。所以这一轮把渐变做成了**两个可调参数**：

| 参数 | 字段 | 说明 |
|------|------|------|
| 主色 | `themeColor` | 圆点的基色（场景主题色） |
| 渐变叠加色 | `gradientColor` | 渐变另一端。**等于主色时就是纯色圆点**，想取消渐变不用找开关 |
| 渐变角度 | `gradientAngle` | 0–360°，默认 145°（就是最初设计稿那颗圆点的方向） |

```css
background:
  radial-gradient(circle at 32% 28%, rgba(255,255,255,.9), transparent 42%),   /* 左上高光 */
  linear-gradient(var(--grad-angle),
    color-mix(in srgb, var(--theme) 62%, #ffffff) 0%,   /* 受光面    */
    var(--theme) 45%,                                   /* 主色      */
    var(--theme2) 100%);                                /* 叠加色    */
box-shadow:                                     /* 双圈光晕：近场主色 + 远场叠加色 */
  0 0 18px color-mix(in srgb, var(--theme) 55%, transparent),
  0 0 30px color-mix(in srgb, var(--theme2) 32%, transparent),
  0 6px 20px rgba(0,0,0,.45);
```

- **默认每一层都协调**：`src/shared/color.ts` 的 `defaultGradientFor()` 按色相自动挑叠加色。默认蓝直接给设计稿的 `#7c3aed`，其它颜色在色相环上**避开 60°–100° 黄绿脏色区**后转 30°：绿→青（`#10b981 → #109cb9`）、橙→红（`#f59e0b → #f5290b`）、紫→洋红（`#8b5cf6 → #d85cf6`）。亮度不动，避免绿色/青色被压成墨蓝。
- **改完立即生效**：设置页「常规 → 外观 → 渐变叠加色 / 渐变角度」拖滑块时，旁边的小圆点预览实时跟、悬浮窗也实时变色（拖动中走 `config:preview` 只推内存不写盘），停手 5 秒或点「保存」才真正落盘，不用重启。
- **两处都能改**：常规页的「外观」卡（单场景，可「套用到所有场景」）和场景编辑弹窗（`#sm-color2 / #sm-angle`）。外观卡还有「改成主色」按钮，一键退回纯色。
- **老配置自动补齐**：`ConfigStore.migrate()` 里 `gradientColor` 缺失时按 `themeColor` 推导、`gradientAngle` 缺失按 145 兜底（`clampGradientAngle` 夹到 0–360 的整数，空串当成没填），所以升级后第一次打开就是蓝紫渐变，不会退化成灰点。
- **兜底**：主题色和叠加色都会直接进 CSS 变量并参与 `color-mix()`，一个非法值会让整条 `background` 失效（圆点直接消失）。所以两个颜色都过 `normalizeThemeColor()` 归一成 `#rrggbb`（`#abc` 自动展开，`blue`/`rgb(...)`/空值退回上一级兜底），渲染进程里还有第二道保险。

### 8.4 应用 / 文件 / 图片也自动读图标（和网页一样）

加项目时不用再手工找图：选完目标就自动把图标和名称填上。

| 类型 | 图标从哪来 | 名称 |
|------|-----------|------|
| 应用 `.app` | 读 `Contents/Info.plist` 的 `CFBundleIconFile` → `Resources/*.icns` → **抽里面最大的内嵌 PNG**（现代图标都是 PNG，实测拿到的就是 1024/256 的原图） | 去掉 `.app` 后的名字 |
| 文件 / 文件夹 | 读不到专用图标，就按扩展名给常用图标：`xlsx→📊` `pdf→📕` `md/txt→📝` `mov→🎬` `flac→🎵` `zip→🗜` `ts→🧑‍💻` `png→🖼`，目录 `📁` | 文件名 |
| 图片 | **直接用这张图本身**当图标（本地路径或 http(s) URL 都行） | 文件名 |
| 网页 | 原来的 favicon 抓取 | 网页标题 |

为什么不用 `app.getFileIcon`：实测在部分环境下它会**直接把主进程打死**（SIGTRAP），为了一个锦上添花的图标功能不值得冒这个险。所以改成自己解析 `.icns`：

- `src/shared/icns.ts`：按容器格式遍历块，取最大的 PNG 表示（纯函数，有单测覆盖截断/损坏/无 PNG 等异常）。
- 老式图标（RLE 裸 RGB，抽不出 PNG）再退一步用系统 `sips` 转一次；`execFile` + 参数数组，不经过 shell。
- 抽到的 PNG 若超过 256px 会先降采样（1024×1024 的图标一张就 500KB，菜单里最多显示 64px）。
- 落盘到 `userData/item-icons/`，和 favicon 共用一套缓存（内容 sha1 命名），离线/原文件被移动都不怕。
- 读不到就退回该类型的常用图标，**不会**在图标栏写一个空值或圆点。

两个入口：

1. **弹窗里**：选完目标自动读取；手动填了路径，光标离开输入框也会读。名称/图标已经是用户自己填的就不覆盖（用 `iconFromProbe` 标记「这个图标是自动读来的」来决定能不能覆盖）。
2. **列表上**：项目库页顶「自动补全图标」——把**所有场景**里图标还是 emoji 的应用/文件/图片项目一次性补全，已经有图片图标的跳过。


### 8.5 内置动作：中英文切换 + 便签（把「输入法悬浮球」的两个能力搬进来）

这两个功能是 FloatDesk 自己实现的，新增了一个项目类型 `action`（内置动作），`target` 里存动作 key：

| key | 名称 | 作用 |
|-----|------|------|
| `ime:switch` | 切换中/英文输入法 | 在中文输入法与英文键盘之间来回切 |
| `note:open` | 打开便签 | 打开桌面便签，自动保存，多组彩色标签，每组可回看 30 版历史 |

**怎么用**：设置 → **工具** → 配置好输入法与便签 → 点「＋ 切换中/英文输入法 / ＋ 打开便签」把动作加进当前场景。加进去以后它就是一个普通项目，改名、换图标、排序、启用停用、删除全都照常。

**中英文切换**

- 真正干活的是 `native/imeswitch.m`（Carbon / TIS 的命令行桥），`npm run build:native` 编成 `bin/imeswitch`，**x86_64 + arm64 通用二进制**。走 TIS 直切不需要「辅助功能」权限，也不受你自己把切换键设成什么影响。
- 「哪一源算中文、哪一源算英文」放在 `src/shared/ime.ts`（纯函数，有单测）：`com.apple.keylayout.*` / `ABC` / `U.S.` 判英文，`*inputmethod*` 且名称或 id 含拼音/五笔/中文等判中文；两边撞到同一个源时丢掉一端，否则切换等于没切。都推断不出来就退化为「在所有输入源之间循环」（原输入法悬浮球的行为）。
- **配置可覆盖**：工具页里可以手动指定中文源与英文源，留空即自动识别。
- **切换后会回读校验**：`TISSelectInputSource` 存在「返回 noErr 但没真切过去」的情况，所以切完再读一次当前源；没生效就自动退回模拟 `Ctrl+Space`（这条路径需要辅助功能权限）。

**验证情况（分两个环境说清楚）**

- ✅ **真机 GUI：已验证生效。** 在悬浮菜单里点「切换中/英文输入法」，日志按序出现
  `输入法切换：com.tencent.inputmethod.wetype.pinyin -> com.apple.keylayout.ABC` →
  `输入法切换：com.apple.keylayout.ABC -> com.tencent.inputmethod.wetype.pinyin` …… 来回切换 10 次全部成功。
  注意这行日志**只在切完回读确认成功之后**才打印，所以它不是「以为切了」，是真的切了。
- ⚠️ **终端环境：切不动。** `list` / `cur` 正常（能列出 6 个输入源、读到当前输入法），
  但 `TISSelectInputSource` 返回 `noErr`、退出码 0，系统输入法与 `com.apple.HIToolbox` 的
  `AppleCurrentKeyboardLayoutInputSourceID` 却都不变——该终端没有窗口会话。
  正因为有这个差异，代码里才必须保留「切完回读校验 + 退回模拟 Ctrl+Space」这道保险。

**便签（富文本）**

便签从「纯文本 textarea」换成了 `contenteditable` 富文本编辑器，写代码片段、列清单、标重点都能直接在便签里做：

| 能力 | 行为 |
|------|------|
| 格式工具栏 | `B` 加粗 · `I` 斜体 · `S` 划线（标「已经做完了」） · `{ }` 行内代码 · `▤` 代码块 · `1.` 有序列表（序列号） · `•` 无序列表 · `清除` 格式 |
| 代码块快速复制 | 每个代码块右上角自动挂一个「复制」按钮（`contenteditable=false`），点一下进系统剪贴板并变绿显示「已复制」；`⌘K` 也能插代码块 |
| 快捷键 | `⌘B` / `⌘I` 原生支持；`⌘⇧X` 划线；工具栏按钮用 `mousedown + preventDefault()` 保住编辑区选区，点了按钮不会丢光标 |
| 粘贴 | 一律降级成纯文本（外部网页的样式会把整张便签带歪，也避免夹带脚本） |
| 自动保存 | 输入后 400ms 防抖落盘；关闭窗口、退出应用前强制再存一次 |
| 多组标签 | 标签栏一组一张纸、每组一个颜色；`＋` 加一组、双击改名、悬停出 `×` 删除（上限 20 组，到顶 `＋` 变灰） |
| 历史 | **每组标签各自**留 30 版（空闲 5 秒记一版）；点某一版先在面板里**预览渲染结果**，确认了才「恢复这一版」，恢复前还会把当前内容存一版以便反悔 |
| 外观 | 7 色预设纸面 + 自定义取色，不透明度 0.3–1，字号 10–28，位置与大小自动记住（最小 280×300，保证工具栏不会把正文挤没） |
| 存储 | `userData/note/notes.json`（多组标签主数据）+ `note_history.json`（按标签分组的历史）+ `note.html` / `note.txt`（当前这一组的镜像，方便别的编辑器打开/搜索），临时文件 + rename 原子写 |

两个容易踩的坑，都在实现里处理掉了：

- **`execCommand('insertHTML', '<pre>…')` 不可靠**：Chromium 会按「粘贴清理」处理，把块级 `<pre>` 拍平成带内联样式的 `<span>`，代码块就没有边框/背景/复制按钮了。所以代码块和行内代码改成**直接建 DOM 节点插进 Range**（`insertAtCaret`），结构完全可控。
- **注入的复制按钮不能存进文件**：序列化前先 `cloneNode` 一份，把 `.code-copy` 全删掉再取 `innerHTML`，否则下次打开会多出一堆死按钮。冒烟测试对此有专门断言。

老版本只有 `note.txt`（纯文本），升级后第一次打开会用 `plainTextToHtml()` 把它转成 HTML 写进 `note.html`（空行分段、行内换行用 `<br>`、`<` `>` 转义），老内容不会丢；老的 `{time, content}` 历史也会被 `normalizeHistoryEntry()` 升级成 `{time, html, text}`。

便签是无边框置顶窗口（拖标题栏移动），不会抢走前台应用焦点，所以切完输入法还能接着打字。

> 便签相关的纯逻辑（颜色/透明度/字号夹取、历史截断、HTML 过滤、老纯文本迁移）在 `src/shared/note.ts`，有单测覆盖；便签窗口的「富文本 → 落盘 → 历史 → 恢复」整条链路已在冒烟测试里用真实窗口跑通（含代码块复制按钮写进剪贴板）。

### 8.6 录制快捷键时先屏蔽系统快捷键（录得上 Command+Shift+4 这类组合键）

**曾经的缺陷**：在设置里录「系统截图 Command+Shift+4」时，组合键一按下去，**系统先执行了截图**，录制框根本收不到这个键，录不进去。

**方案**：录制期间装一个**系统级键盘事件 tap**（`native/keyblock.m` → `bin/keyblock`），把键盘事件全部吞掉——系统和其他应用都不会执行，同时把识别出的组合键回报给设置页当录制输入：

```
点「录制」 → 主进程 spawn bin/keyblock（session 级 tap，吞掉所有键盘事件）
           → 用户按 Command+Shift+4 → 系统不执行；keyblock 上报 "KEY Command+Shift+4"
           → 设置页录到这个组合键，写入配置，杀掉 keyblock，键盘立即恢复
```

实现要点：

- **为什么不能只吞不报**：tap 会把设置页自己的 `keydown` 一起吞掉，录制框反而收不到键。所以 keyblock 在吞事件的同时把组合键打到 stdout，由主进程（`src/main/KeyBlocker.ts`）逐行转发给设置页（`rec:key`）。
- **三档回报**：`KEY <accelerator>`（按下完整组合键，录它）/ `HELD <mods>`（只按住修饰键，更新「已按住 Command…」提示）/ `ESCAPE`（取消录制）。
- **默认开启，可关**：「常规 → 行为」里有「录制时屏蔽系统快捷键」勾选（配置字段 `appearance.blockKeysWhileRecording`，默认 `true`）。关掉后完全走原来的 DOM 捕获，keyblock 不起。
- **双保险防键盘锁死**：keyblock 自带 30 秒安全阀自动退出；录制一结束（录到 / Esc / 超时 / 再点一次）主进程立即 SIGTERM 杀进程；设置窗口关闭、应用退出时也会兜底停掉。
- **权限**：与「发送组合键」共用同一个「辅助功能」权限；keyblock 装不上 tap（没权限）时主进程回报 `rec:native = false`，设置页自动退回 DOM 捕获，不会卡死。
- 真机链路自检：`env -u ELECTRON_RUN_AS_NODE npx electron scripts/keyblock-live-check.js --no-sandbox --disable-gpu`（真实 keyblock + 真实 sendkey 发 Command+Shift+4，验证「录得上 + 截图不触发 + 录完键盘恢复 + 关勾选后仍能录」）。

### 8.7 内部图标库文件夹 + 相同项目图标同步到全场景

**图标库**：`~/Library/Application Support/FloatDesk/icon-library/` 是 FloatDesk 内部的图标文件夹（`src/main/IconLibrary.ts`），两种用法：

- **Finder 里直接管理**：设置 → 工具 →「图标库」卡片的「打开文件夹」按钮直达；往里扔图标文件、删除、改名都随意，设置页点「刷新」即可看到。
- **设置页里拖放**：把图标文件拖到工具页卡片或选图浮层里的虚线框即可加入（支持一次多选）；从浏览器里拖来的图拿不到本地路径，会自动走 dataURL 兜底，同样能收。
- **给项目用**：编辑项目时点「从图标库选图」→ 浮层里点哪个用哪个。选用时主进程会**复制一份进 item-icons 缓存**再回填，所以以后在库里删掉这个文件，已经用上它的项目也不会变空白图。
- 安全与卫生：只收图片（扩展名白名单 + 文件头魔数双重校验，单个 ≤8MB）；同名同内容不重复写；库外路径一律拒删（防 `../` 越界）；`shared/items.ts` 之外的所有路径操作都在主进程，渲染进程只传路径、不碰 fs。

**相同项目图标同步**：同一个项目（同名 + 同目标 + 同类型，`shared/items.ts` 的 `sameProjectMatches` 判定）被加进多个场景时，它们是同一个东西。编辑其中一个项目时，若其他场景还有相同项目，编辑弹窗会出现「**同步到全场景**」勾选（提示数量），保存时勾选即把图标一并应用到那些项目；悬浮窗右键「更换图标…」换完图标也会弹出询问。不勾选就只改当前场景，行为与从前一致。

### 8.8 项目库：预制项目按类型浏览、中英文检索、网址识别、小加号加到场景

设置侧栏新增「**项目库**」页，把「造项目」这件事从「一个个手填」变成「从库里挑」。

- **预制项目**：内置 155 条常用条目（`src/shared/itemLibrary.ts`），覆盖应用（78 条：访达 / 启动台 / Safari / 备忘录 / 终端 / 活动监视器 / 磁盘工具 / 截图 / 钥匙串 / 快捷指令… 加常见第三方）、网页（30 条：GitHub / Gmail / ChatGPT / 飞书 / 淘宝 / 12306…）、快捷键（36 条：复制 / 粘贴 / 截图 / 录屏 / 聚焦 / 全屏…）、文件夹（9 条：下载 / 桌面 / 文稿 / 影片 / 应用程序…）与内置动作（2 条：中英文切换 / 打开便签）。预制项**不写进用户配置**，只是渲染层常量；应用类条目会按本机实际安装情况过滤（没装的不摆出来）。
- **按类型分类的下拉**：全部类型 / **mac 系统** / 网页 / 应用 / 文件 / 图片 / 快捷键 / 内置动作，选完立刻筛（「mac 系统」与其它分类互斥，见 8.10）。
- **中英文检索**：检索框同时认名称、类型名和 `keywords` 别名（每条预制都带中英文别名，如 GitHub 挂了「代码托管 / 代码 / git / 开发」），所以搜「代码」能搜到 GitHub，搜「terminal」能搜到终端，大小写不敏感。
- **输入网址直接识别**：检索框里粘一个网址（`https://…` / `www.…` / 裸域名都行）时，结果区顶部会出现「**识别为网址**」卡片，点一下或点小加号即读取站点标题与 favicon 后建项目（与「添加网址」模式共用同一套 `addWebByUrl` 逻辑）。加完自动清空检索词，避免重复添加。
- **一个输入框两种模式（检索 ⇄ 添加网址）**：原先「项目管理」页那个独立的「添加网页」输入框已删掉（整页已并入项目库，见 8.14），两处功能合并到「项目库」页的同一个输入框里 —— 输入框**右下角有一颗小切换按钮**（🔍 检索 / 🔗 网址，样式沿用设置页的深色圆角卡片语言），点一下就切模式：检索模式右边跟「全部类型」下拉，网址模式右边跟「读取并添加」按钮。网址模式下回车即读取添加。
- **只有 ＋ 才加入场景，点卡片其它位置 = 编辑项目**：左栏卡片右上角的小 **＋** 是**唯一**把它加进场景的入口；点卡片其它位置（名称、图标、空白处）打开的是**编辑弹窗**，表单按该条目预填，改完**存回项目库**，**不会**顺带加进场景（弹窗里有一行提示明说这点，编辑「全局热键 / 启用 / 同步到全场景」这类只属于场景项目的行也一并隐藏）。改预制项目会另存一份到「我的收藏」（预制项是公共资源，不能直接改写）；改自己的收藏则原地更新，弹窗里多一颗「从项目库移除」。已经加进场景的条目再点卡片，编辑的是场景里那一条。
- **小加号添加到场景**：每张卡片右上角是一颗小 **＋**，点一下就把该项目加到所选场景；右栏「场景已添加」每行也有「收藏」按钮，把自己的项目存进「我的收藏」，之后在别的场景一键复用。
- **左右两栏（加进去的和没加进去的分开看）**：
  - **左栏「项目库 · 还没加入场景」** —— 库里还没加进这个场景的项目，每张卡片带小 **＋**（**只有 ＋ 才会加进场景**）；点卡片其它位置是**编辑**这个条目（存回项目库，不进场景）。已经在场景里的不再重复出现在这里（同一性判定：类型 + 名称 + 目标 + 组合键）。
  - **右栏「场景 · 场景已添加」** —— 当前场景里已有的全部项目，一行一个，**项目管理的所有操作都在行内**：启用/停用开关、**↑↓** 排序、**编辑 / 复制 / 收藏**、右侧红色 **×**（**从场景移除**，移除后它自动回到左栏，方便换成别的项目）。移除会连带清理其它场景里指向它的全局触发项。
  - 「我的收藏」是例外：已经在当前场景里的收藏项仍然显示，标一个「已在场景」角标且不给加号（免得用户收藏的东西凭空消失、也没法从库里清理）。
  - 有检索条件时，右栏里不匹配当前条件的行会淡显，但照样能移除。
- 场景下拉默认跟随项目库页顶部选中的场景，添加后会提示「已添加「xxx」到「场景名」」，右栏标题上的计数实时更新。
- 纯函数（`looksLikeUrl` / `libraryMatches` / `filterLibrary`）放在 `src/shared/itemLibrary.ts` 供单测覆盖；渲染进程是经典脚本不能 import 值，设置页各存一份同逻辑副本（与 `sameProjectMatches` 同样的约定，改动时两边同步）。
- 预制项的数据合法性由 `src/test/itemlibrary.test.ts` 兜住：每条都当成菜单项过一遍 `validateItem`，保证加进场景后不会被配置校验打回。

### 8.9 macOS 原生图标 + 本机应用 + 老路径自动纠正（这一轮的重点）

苹果从 Catalina 起把系统应用搬到了 `/System/Applications`，工具在 `Utilities` 下，钥匙串/归档工具在 `CoreServices/Applications`，Finder 更是在 `CoreServices` 里。之前预制库里写的是 `/Applications/Notes.app`、`/Applications/Utilities/Terminal.app` 这种「Windows 思维」路径 —— **图标读不到、点了也打不开**（悬浮球上只剩一个 emoji）。这一轮把整条链路改成 macOS 原生：

- **路径解析（`src/shared/macapps.ts`，纯函数 + 单测）**：`resolveInstalledApp()` 按 bundle 名在 `MAC_APP_DIRS`（`/Applications` → `/System/Applications` → `Utilities` → `CoreServices/Applications` → `CoreServices` → `~/Applications`）里找真实路径，还带版本别名表（`Launchpad.app` ⇄ `Apps.app`、`System Preferences.app` → `System Settings.app`）。
- **启动体检（`src/main/Repair.ts`）**：启动 1.5s 后静默跑一遍——
  1. app 类型项目 target 不存在 → 按 bundle 名找回来并改写（老配置里的 `/Applications/日历.app` 自动变成 `/System/Applications/Calendar.app`）；
  2. app / file 项目的图标还是 emoji → 读一次原生图标写进配置；
  3. **只补没图标的**，用户手挑的图片图标一律不动，没装的应用也不瞎改。
  改完写盘并广播，悬浮球上的图标当场就变。
- **原生图标来源**：应用读 `.app/Contents/Resources/*.icns`（`plutil` 取 `CFBundleIconFile` → 内嵌 PNG 优先，老式 icns 走 `sips`），缩到 256px 后按内容 sha1 落到 `userData/item-icons/`；目录读 `CoreTypes.bundle` 里 Finder 同款那套（下载 / 桌面 / 文稿 / 图片 / 音乐 / 影片 / 公共 / 应用程序 / 主目录）。带内存 + 落盘缓存（`userData/app-icon-cache.json`，key 是路径 + mtime，应用升级换图标会自动失效重读）。
- **本机应用一节**：项目库页左栏最前面列出**这台 Mac 真实装了的应用**（`src/main/MacApps.ts` 扫标准目录，排除卸载器/更新器这类噪音），图标就是 Finder 里那个样子，点 ＋ 直接加进场景。和预制库按路径去重，不会重复出现。
- **其余类型给 macOS 风格图标**：网页 / 快捷键 / 内置动作这类没有原生图标的，emoji 外面套一层圆角方块（26% 圆角 + 淡渐变 + 内高光），和真图标摆在一起观感统一，不再是一颗玻璃圆里孤零零一个表情。
- **去 Windows 化**：
  - 删掉 `electron-squirrel-startup`（Windows 安装器钩子）与其依赖，主进程启动不再有这段 Windows 分支；
  - 预制库里「资源管理器 / 任务管理器 / 记事本」这类 Windows 术语别名清掉，换成 mac 说法；
  - 死掉的「微信网页版」（`wx.qq.com` 早已停用）换成微信 App；
  - 快捷键全部检查为 `command/option/control` 写法，没有 `ctrl` / `win`。
- **自检**：`scripts/mac-native-check.js`（19 条：路径纠正、图标落盘为 PNG、目录图标、用户图标不被覆盖、已卸载应用不瞎改、预制库全部指向真实 .app、本机应用扫描）；`scripts/float-icons-shot.js`（4 条 + 截图：菜单里原生图标与 emoji 方块并存）；`scripts/library-shot.js` 增加「本机应用（N）分区」「卡片图标是原生图片」断言。
- **新增单测**：`src/test/macapps.test.ts`（9 组）+ `itemlibrary.test.ts` 追加 5 组 macOS 约束（应用路径不许写死 `/Applications`、快捷键不许 `ctrl`、不许有 Windows 术语…），单测从 107 增至 **121**。

### 8.10 项目库新增「mac 系统」分类：系统自带的项目归到一处

系统自带的那些应用、文件夹和系统级快捷键以前散在「应用 / 文件 / 快捷键」三个分类里，翻起来费劲。现在项目库的类型下拉里多了一个 **「mac 系统」**，排在「全部类型」下面第一位：

- **虚拟分类，不是第四种类型**：`mac` 只存在于筛选层（`LIBRARY_TYPES`），条目本身的 `type` 仍然是 `app` / `file` / `shortcut`，所以加进场景、执行、校验全都不受影响。分类靠 `LibraryItem.system` 这个标记来判断。
- **哪些算系统自带**：`/System/` 下的应用（访达 / 启动台 / Safari / 备忘录 / 终端 / 活动监视器 / 磁盘工具 / 钥匙串…）、9 条系统标准文件夹（下载 / 桌面 / 文稿 / 图片 / 影片 / 音乐 / 公共 / 主目录 / 应用程序）、9 条系统级快捷键（截图、全屏截图、录屏、聚焦、表情符号、全屏、程序坞、切换应用、锁屏）。第三方应用（微信 / Chrome / VS Code…）和普通快捷键不标。本机应用扫描出来的应用也按路径自动判定（`/System/` 开头才标）。
- **和其它分类互斥**：`matchLibraryType()` 保证同一项目只出现在一个分类里 —— 选「mac 系统」只有系统条目；选「应用 / 文件 / 快捷键」则**排除**系统条目。避免同一样东西在三处重复出现（这也是「归到这个类型下」的字面意思）。
- **看得出是系统的**：卡片图标右上角一颗小蓝点（`title="macOS 系统自带"`），副标题写成「mac 系统 · Finder / Downloads / ⌘⇧4」这种目标简称，完整路径留在悬停提示里。
- **搜索也能搜到**：搜「mac」「macos」「系统」「mac 系统」会把系统条目捞出来。
- **顺手修的两处**：
  1. **副标题截断**：卡片最小宽度从 152px 提到 216px。原先留给文字只有 ~56px，副标题清一色被切成「mac 系统 ...」，等于没有信息；现在绝大多数能完整显示（剩 5 条超长英文名如 Bluetooth File Exchange 会省略）。
  2. **快捷键显示成符号**：`command+shift+4` 这种内部写法在副标题里改成 `⌘⇧4`（`prettyKey()`），否则一条快捷键就能把副标题撑满。
- **标记要能活过重启**：项目库条目的字段白名单在 `ConfigStore` 里，漏了 `system` 的话，收藏的系统项目重启后会悄悄掉回「应用」分类。已在白名单补上，并在「收藏到项目库」和「编辑项目库条目」两处用 `isSystemBuiltin()` 按「类型 + 目标」回查预制库，保证来回转一圈仍然是系统项目。
- **自检**：单测追加 6 组（分类顺序、互斥规则、`filterLibrary('','mac')` 全是 system、应用/文件/快捷键分类不含 system、系统应用标记正确且第三方未误标、搜「mac 系统」只剩系统条目）；`library-shot.js` 追加 11 条 UI 断言（下拉顺序、选 mac 只剩带蓝点的卡片、选应用/文件不含系统条目、切回全部类型两者都在、副标题不被挤成一截、快捷键显示成符号、「文件」分类空了会说清原因）；`mac-native-check.js` 追加 2 条（`system` 标记能落盘、普通收藏不被误标）。


### 8.11 菜单音效：鼠标移到按钮上清脆一响（预制 18 个音效）

菜单开合、扫过按钮时给一点声音反馈 —— 主要是「移动到按钮上」那一下，要**清脆**、不拖泥带水。

- **三个事件各挑一个音效**：`移到按钮上`（默认 **清脆叮 Tink**）、`点击项目`（默认 **轻弹 Pop**）、`展开 / 收起`（默认 **不播放** —— 开合太频繁，加声音容易吵）。总开关 + 音量滑杆（0–100，默认 45%），每个下拉旁边一颗「试听」。
- **18 个预制音效**，分两组：
  - **macOS 系统音效（14 个）**：Tink / Pop / Morse / Purr / Bottle / Glass / Ping / Frog / Blow / Funk / Hero / Sosumi / Submarine / Basso，就是系统「提示音」里的那套。Chromium 不能解 AIFF，所以主进程用系统自带的 `afconvert` 转成单声道 22.05kHz WAV，落在 `userData/sounds/*.wav`，渲染进程再用 WebAudio 解码播放（data URL + `atob` → `decodeAudioData`，不碰网络也不受 CSP 限制）。启动后 0.8s 会按配置预热这几个文件，第一次悬停不用等转换。
  - **合成音效（4 个）**：木敲 / 干脆按键 / 水滴 / 木琴 —— 不依赖任何文件，渲染进程直接算波形（噪声脉冲经高通+低通+指数衰减，或带泛音的正弦滑音）。系统音效缺失、转码失败时也会自动退到合成音效，**不会出现「划过没声音还查不出原因」**。
- **不吵人的细节**：
  - 悬停音效默认只播前面一小截（`hoverSec`，Tink 0.34s），长音效（Glass 1.65s）不会拖尾；
  - 40ms 内只响一次 —— 快速扫过一整圈不会糊成一片；
  - 同时最多 5 个声源，超出把最早的掐掉；每个声音 4ms 起音 + 末尾 25ms 淡出，避免爆音/咔哒；
  - 悬停比点击轻（增益 ×0.55），点击最实（×1）。
- **自动播放限制**：Chromium 默认要「用户手势」才允许 AudioContext 出声，而悬停本身不算手势。主进程统一加了 `--autoplay-policy=no-user-gesture-required`（桌面应用不需要网页那套限制），并在第一次点圆点时再 `resume()` 一次兜底。
- **配置**：`AppConfig.sound = { enabled, hover, click, open, volume }`；老配置没有这一节，`ConfigStore.migrate()` 用 `normalizeSoundConfig()` 补齐（音效 id 写错回默认、音量夹到 0–100），悬浮窗每次收到 `scene:changed` 就重新 `configure()`，改完立即生效。
- **一处共享，两处使用**：播放引擎是 `src/renderer/shared/sound.ts`（编译成 `dist/renderer/shared/sound.js`，经典脚本挂 `window.FDSound`），悬浮窗和设置页用 `<script src="../shared/sound.js">` 各引一份 —— 避免设置页和菜单各写一套 WebAudio。音效清单的权威版本在 `src/shared/sounds.ts`，设置页通过 IPC（`sound:list`）取，不在渲染层复制表。
- **自检**：`scripts/sound-check.js`（20 条：aiff→WAV 转码/缓存/复用、合成音效不读文件、AudioContext 必须 running、悬停发声、40ms 节流、总开关、选「不播放」、点击发声、点击后收起再展开、取不到文件时退到合成音效）+ `ui-smoke.js` 追加 5 条（卡片存在、默认 Tink/Pop/不播放、下拉两组齐全、改值写进配置、音量 70% 同步、试听可点）+ `sounds.test.ts` 8 组（清单完整性、sys/synth 不混、默认值、`normalizeSoundConfig`、`volumeToGain` 单调、`hoverSeconds` 夹取）。

### 8.12 设置页全局禁止选中文字：拖滑杆不再误选（只有输入框保留复制粘贴）

**反馈的现象**：拖音量 / 不透明度这类滑杆时，鼠标从滑杆划到旁边的说明文字上，整段文字被选中变蓝，滑杆跟着卡住不动 —— 想调 70% 调到一半就「拉不动了」。

- **样式层（`src/renderer/settings/index.html`）**：
  - `html, body { user-select: none }` —— 说明文字、卡片、标题、日志区全都不可选中；
  - `input, textarea, select, [contenteditable="true"] { user-select: text }` —— **能自己打字进去的地方例外**，那里必须能选中、能 `⌘C` / `⌘V`；
  - `input[type=range|checkbox|color], button { user-select: none }` —— 滑杆/开关/取色器/按钮本身也不参与选中；
  - `img { -webkit-user-drag: none }` —— 图标不会被拖出小幽灵图（拖卡片时容易误触）。
- **键盘层（`src/renderer/settings/app.ts`）**：CSS 只能挡鼠标，`⌘A` 照样能选中全页（拖滑杆时手抖按住 ⌘ 就中招），所以在 `document` 上加了一层捕获阶段的 `keydown` 守卫：目标不是「能打字的地方」时，`⌘A / ⌘C / ⌘X` 直接 `preventDefault()`；是输入框就放行。录制快捷键时自动让路（否则 `⌘A` 这类组合键录不下来），第一次按 `⌘C` 会提示一次「要复制诊断信息请到关于页点按钮」。
  - 判定「能打字的地方」用的是**具体控件类型**（`text/search/url/tel/email/password/number/date…` 这些 `<input type>`、`textarea`、`select`、`contenteditable`），而不是笼统的 `<input>` —— 否则 `⌘A` 落到滑杆上也会被当成输入框放行。
- **兜底**：`mousedown` 落在 `input[type=range]` 上时先把已有选区清掉，防止某些 Chromium 版本拖滑杆顺手起一个文档选区。
- **右键菜单跟着收口**（`src/main/appMenu.ts`）：`buildEditMenuSpec(isEditable=false, …)` 现在一律返回 `null` —— 页面既然不许选中，非输入区就不该再出现「复制」这种点了也没用的项。
- **诊断信息改走按钮**：日志区不能选中了，所以「关于 → 诊断」新加一颗 **「复制诊断信息」** 按钮：点一下把诊断 + `floatdesk.log` 一起写进系统剪贴板（走新 IPC `clipboard:write` → 主进程 `clipboard.writeText`，比渲染进程的 `navigator.clipboard` 稳），并 toast「已复制诊断信息」。
- **自检**：
  - `ui-smoke.js` 追加 6 条：整体 `user-select: none`（说明文字/滑杆都不可选）、**在说明文字上拖鼠标不产生选区**、**从滑杆往外拖不产生选区**、**对照组（临时放开 user-select 后同样拖拽确实能选中）**、非输入区 `⌘A` 被拦而输入框 `⌘A` 照常、诊断按钮真的写进剪贴板。
  - 新增 `scripts/no-select-shot.js`（7 条）：用 CDP 发**真实鼠标事件**做拖选（合成事件不会触发原生拖选，测不出真效果），其中一条专门验证**输入框里拖拽仍能选中**（需求里要保留的那部分），拍三张对照图 —— `settings-nosel.png`（拖过文字无蓝色选区）/ `settings-nosel-control.png`（放开后同样拖拽能选中，证明前一张不是空跑）/ `settings-copydiag.png`（复制按钮 + toast）。

### 8.13 常规 + 外观合并成一页 · 改完不立刻写盘（停手 5 秒 / 点按钮才存）

**反馈的两件事**：①「常规」和「外观」两页翻来翻去太碎，页面也拉得太长；② 拖滑杆时**一改就存**，存完主进程广播回来把整页 DOM 重建，正在拖的那根滑杆被换成新节点 —— 手一松就断，越拖越别扭。

**① 合并 + 紧凑**

- 导航从 8 项收到 **7 项**（常规 / 场景管理 / 快捷键 / 项目管理 / 项目库 / 工具 / 关于），`#view-appearance` 整块删掉。（8.14 又把「项目管理」并入项目库，现在共 **6 项**）
- 常规页改成**两栏卡片**（`.grid2`，`minmax(0,1.04fr) minmax(0,1fr)`；左 3 张 / 右 4 张）：
  - 左栏：**场景**（下拉切场景 + 「切换到当前场景」+「编辑信息」）→ **外观**（主题色 / 渐变叠加色 / 渐变角度 / 玻璃透明度 / 圆点大小 / 环形半径 / 图标尺寸 / 菜单透明度 / 菜单布局 / 显示名称，右上角「套用到所有场景」）→ **悬浮球**
  - 右栏：**行为** → **菜单音效** → **右键场景选区** → **全局快捷键**
- 间距整体收紧：`.main` padding `18px 24px 26px`、`.card` padding `13px 15px 14px`、`.row` 上下 6px、`label` 宽 112px；滑杆从写死 `width:240px` 改成 `flex:1 1 120px; max-width:210px`（两栏后行变窄，写死会顶出卡片）；数字输入框 `input.num` 收到 92px。
- 窗口默认尺寸跟着放大到 **1180×800**（`SettingsWindow.ts`），否则 980 宽会触发 1020px 断点收成单栏、反而更长；`minWidth` 900，小于断点自动回到单栏。

**② 保存节奏：连续控件只预览，停手才写盘**

| 控件类型 | 行为 |
|----------|------|
| 滑杆 / 取色器 / 数字框（连续） | `input` 时只更新内存 + 读数 + 80ms 节流推 `config:preview` → 5 秒防抖定时器刷新；`change` 时重新计时 → **停手 5 秒自动保存**（不写备份） |

### 8.15 场景管理改成「场景库」：左右分屏 · 行内只有 编辑 / 项目 / ＋|－ · 停用的场景数据一条不丢

**② 悬浮球窗口位置：改用「圆点锚点」，切场景不再漂**

- 根因：窗口是正方形、圆点在正中心，但 `dotSize` / `ringRadius` 是**每个场景独立**的，收起/展开尺寸都随场景变。老 `resize()` 从**当前 bounds** 反算中心再摆回去，一旦窗口贴近屏幕边缘就被 `workArea` 夹住 —— 中心被挪走、圆点跟着跳，缩回小尺寸也不会回到原位（一路往左飘）。场景尺寸差越大、越靠边，跳得越明显。

### 8.17 项目库支持浏览器书签批量导入

**反馈**：「项目库，支持浏览器书签批量导入功能，方便把浏览器的书签转移到这里」。

**入口**：项目库页顶的「**导入书签**」按钮（在「自动补全图标」左边）。点它 → 系统选择框（默认落在 `~/Downloads`）→ 选浏览器导出的 HTML 文件。四个浏览器的导出位置都写在弹窗提示里：

| 浏览器 | 导出路径 |
|---|---|
| Chrome / Edge | 书签管理器 → 右上角 `⋮` → 导出书签 |
| Safari | 文件 → 导出 → 书签 |
| Firefox | 书签 → 管理 → 导入和备份 → 导出为 HTML |

**解析（`src/shared/bookmarks.ts`，纯函数 + 12 条单测）**：四个浏览器的导出都是 Netscape 书签格式（`<DL><p>` / `<DT><H3>` / `<DT><A HREF ICON>`），所以只需要一个解析器。用**栈**处理嵌套（`<DL>` 进栈、`</DL>` 出栈），每个节点带上 `depth` 与 `path`（文件夹路径数组），出来的是一棵可折叠的树。

| 处理 | 说明 |
|---|---|
| 协议白名单 | 只收 `http(s)`；裸域名自动补 `https://`；`javascript:` / `place:` / `chrome:` / `data:` / `about:` / `file:` 一律跳过并计入「跳过 N 条非网页」 |
| 标题清洗 | 去标签、解 HTML 实体、压空白、超 80 字截断；没标题就退回域名 |
| 图标 | Chrome/Edge 会把 favicon 以 `data:image/...` 写进导出文件，直接沿用；超过 12KB 的丢掉换成 🔗 |
| 容错 | 空文件 / 乱码 / 大小写混杂 / 属性不带引号都不抛错，最差返回 0 条链接 |

**导入弹窗**（宽版 780px，树区域最高 46vh 独立滚动）：

| 部分 | 行为 |
|---|---|
| 目标单选 | **先放进项目库（推荐）** / **直接加进场景「当前场景名」**。默认前者 —— 书签动辄几百条，全塞进悬浮环会把菜单撑爆，先落库再挑着 `＋` 才是正常用法 |
| 检索 | 按书名 / 网址 / 文件夹路径过滤（`filterBookmarks`），只重画树，检索框不重建、输入焦点不丢 |
| 树 | 文件夹可折叠（`▾/▸`）；文件夹的勾选框是「全选 / 全不选这一支」的快捷方式，带**半选态**（`indeterminate`），右侧显示「已选/总数 · N 已存在」 |
| 去重 | 已经在「项目库 / 当前场景 / 内置预制」里的网址显示成**已存在**、默认不勾、勾选框禁用；同一份文件导两次不会产生重复项 |
| 计数 | 底部按钮直接写「导入所选（N）」，N=0 时禁用 |

**「已存在」的判定口径跟着目标走**（这里踩过一次坑）：一开始固定按「预制 + 收藏 + 当前场景」判重，结果**先导进项目库再想直接进场景**时，刚入库的网址把自己全判成了重复 → `已选 0`、一条也加不进场景。现在切单选会重算去重集合（目标是场景时只看当前场景的 `items`）并重算默认勾选，头部那句「N 条已经存在」的措辞也跟着变成「已经在当前场景里」。

**落库时**：目标=项目库 → 逐条 push 进 `cfg.itemLibrary`（`type: 'web'`，`keywords` 里塞 `[书名, ...文件夹路径]`，以后搜「技术」「工具」能直接搜到这批书签）；目标=场景 → push 进 `sc.items` 后 `renormalize` 重排 `order`。两边都会**再按网址去重一次**（同一个文件里重复的书签只落一条）。

**自检**：`scripts/bookmarks-import-check.js`（**28** 条，`npm run smoke:bookmarks`）—— 造一份含 3 层文件夹、`javascript:` 坏书签、文件内重复 GitHub、`data:image` 图标的真实格式书签文件，用等价的 IPC 桩跑真实渲染页：按钮/宽版弹窗/树节点数（21 条链接 / 4 个文件夹）/头部统计/默认勾选 20 条/检索过滤/文件夹一键清空与恢复/导入落库 19 条（重复的折叠）/关键词带文件夹路径/图标是 `data:image`/二次导入全部「已存在」且不新增/切「直接进场景」重算为 21 可选并落 20 条/右栏渲染 20 行。截图 `docs/screenshots/bookmarks-import.png`。

### 8.18 便签：多组彩色标签 + 每组 30 版历史（先预览再恢复）+ 划线

**反馈**：「书签添加更多可恢复版本，可预览内容在恢复，添加划线功能，表示已经完成，添加多组标签加号按钮，点加加号加一组标签导航用不同颜色区分，类似 windows 便签」。

**数据模型换了**（`src/shared/note.ts` 纯函数 + `src/main/NoteStore.ts` 落盘）：

| 文件 | 内容 |
|---|---|
| `notes.json` | 主数据 `{ active, pages: [{ id, title, color, html, text, updatedAt }] }` |
| `note_history.json` | `{ version: 2, pages: { p1: [{time,html,text}], p2: [...] } }` —— **每组标签各自一份历史** |
| `note.html` / `note.txt` | 当前这一组的镜像（外部编辑器 / 全文搜索 / 老版本升级都靠它） |

老数据一条都不丢：没有 `notes.json` 时，老的 `note.html` / `note.txt` 会被升成「便签 1」；老的一维 `note_history.json` 数组会被整体归到第一组标签下。

**标签栏**（`#tabs`）：一组一张纸，颜色取自 10 色标签色板按新建顺序循环（`NOTE_TAB_COLORS`，比纸面色板更饱和，浅色纸底上一眼分得清）。当前那组的底色是**实色**、字色按亮度自动换（`tabInk`：亮底用深字、深底用白字），其余是 22% 淡染。`＋` 在滚动区**外面固定住**（组多了不会跟着标签滚走），满 20 组后变灰。双击标签名就地变输入框改名（回车提交 / Esc 取消，脏检查后才写盘）。悬停出现 `×`，有内容时会 `confirm` 一句再删，删掉的组连它那份历史一起清（`pruneHistory`）。

**结构只有一份实现**：渲染进程**不做** `addNotePage/patchNotePage` 这套逻辑，而是把「整本便签 + 操作名」发给主进程（`note:page`），主进程用 `shared/note.ts` 的纯函数算好再回传。这样标签结构不会出现前后端两套实现慢慢跑偏的问题（这一条是项目里反复踩过的坑）。

**历史：先预览，再恢复**：点「历史」→ 面板列出**当前这组**的 30 版（`版本 N · 时间 · 字数` + 一行摘要）。**点某一版不会直接改正文**，而是弹出一层预览，把那一版的富文本按渲染后的样子铺开；确认无误再点「恢复这一版」。恢复前会先把「现在的内容」记一版进历史 —— 恢复错了还能再点回去（这一条自检里有专门断言）。

**划线**：工具栏 `S` 按钮（`execCommand('strikeThrough')`，Chromium 产出 `<strike>`）+ `⌘⇧X`。样式上 `<s>/<strike>/<del>` 和内联 `line-through` 都补齐，线宽 1.5px、字透明度 62% —— 「一眼看出这行已经做完了」。

**自检**：`scripts/note-pages-check.js`（**39** 条，`npm run smoke:notepages`）—— 真窗口 + 真渲染进程 + 真 `NoteStore`：初始一组/有 `＋` 无 `×`、划线按钮产出 `<strike>` 且计算样式含 `line-through`、点 `＋` 后自动切到空的新组且颜色不同、两组正文互不串且各自落盘、双击改名并落盘、连写 12 版历史（突破原来 3 版上限）、历史面板列出 12 版、点某一版只弹预览且正文一个字没动、点恢复后正文变成那一版且恢复前内容留在历史最上、`×` 删当前组后落到剩下那组且历史被清、重开窗口组数/名字/正文/划线都还在、加到 8 组时颜色互不相同且 `＋` 仍在可视区、满 20 组后不再新增。截图 `docs/screenshots/note-tabs.png` / `note-tabs-many.png` / `note-history.png` / `note-history-preview.png`。

## 9. 交互缺陷修复记录（圆点「能看见但点不动」）

真机反馈过三轮「圆点显示正常，但拖不动、左右键都没反应」。最终定位到**两个独立根因**，均已修复：

| # | 根因 | 现象 | 修复 |
|---|------|------|------|
| 1 | 渲染脚本被 `tsc` 按 CommonJS 编译（源码里有 `export {}`），产物首行是 `Object.defineProperty(exports, "__esModule", …)`。浏览器里没有 `exports`，脚本**一加载就抛 ReferenceError**，后面所有 `addEventListener` 都没执行 | 圆点可见（CSS 生效）但完全无交互；`floatdesk.log` 里没有任何 `悬浮窗 resize` 记录 | 三个渲染脚本改为 IIFE 包裹、删除 `export {}`。产物首行为 `(function () {`，全文除注释外不再引用 `exports` |
| 2 | `second-instance` 回调里调了 `setIgnoreMouseEvents(true, { forward: true })`。重复双击启动器（或第二次打开）时，新实例把**已在运行的**圆点设成了点击穿透 | 鼠标移上去有「小手」光标，但左右键点击全部穿透到下层窗口 | 已删除该调用，改为 `show()` + `focus()`。全项目不再有 `setIgnoreMouseEvents(true, …)` |

顺带做的加固：

- **拖动改为主进程驱动**：渲染进程只发 `float:dragStart` / `float:dragEnd`，位移由主进程每 16ms 读 `screen.getCursorScreenPoint()` 计算（原地保持光标与窗口的相对偏移），超过 3px 才算「拖动」。原因：窗口一旦移动，Chromium 可能不再派发 `mousemove`，纯渲染进程拖动会中途卡死。另有 20 秒兜底与失焦即结束，避免窗口「自己跟着光标跑」。
- **点击判定**：`mouseup` 时向主进程询问 `moved`，未移动才算点击 → 展开/收起。
- **右键菜单**：圆点右键弹出原生菜单（打开设置 / 切换场景 / 隐藏悬浮台 / 退出）。
- **渲染进程诊断日志**：渲染侧通过 `float:log` 把「已就绪 / 事件已绑定 / dragEnd moved=… / onerror」写进 `floatdesk.log`。以后再出现「点了没反应」，看日志就能立刻分辨是「脚本没跑」还是「事件没进来」。
- **`acceptFirstMouse: true`**：未激活窗口的第一次点击直接交给页面，不被系统吞掉。

> 上述修复已在真实 Electron 运行时验证：日志按序出现 `悬浮窗渲染进程已就绪` → `悬浮窗初始化完成（事件已绑定）` → `dragStart/dragEnd moved=true`（窗口坐标随拖动改变）→ `悬浮窗 resize -> expanded 404px / collapsed 120px`（点击展开收起生效）。

## 10. 已知限制

- **网格 / 列表菜单布局**：设置界面提供选项，但首版渲染仍按环形（规格 P2 后续增强）。
- **向其他应用发送快捷键**：仅支持单字符键 + 修饰键（如 `command+c`）；特殊键（方向键、功能键）将在后续版本支持。需要 macOS 辅助功能权限。
- **辅助功能权限**：首次使用「发送快捷键」必须由用户在系统设置中手动授予，程序只能检测状态并引导。
- **`.dmg` 公证**：开发版本本机可跑；公开分发需 Apple Developer ID 签名 + 公证，本仓库未内置该配置。
- **全局快捷键冲突**：与系统或其他应用冲突时主程序会提示，不会静默生效。
- **输入法切换的兜底需要权限**：TIS 直切本身不需要权限，但兜底路径（模拟 `Ctrl+Space`）需要「辅助功能」权限；未授权时切换会失败并提示。
- **菜单音效依赖 macOS 自带的那套提示音**：系统音效从 `/System/Library/Sounds` 读，用 `afconvert` 转成 WAV（首次播放前会转，之后走缓存）。换到非 macOS 环境或系统音效被删掉时，会自动退到 4 个合成音效，不会完全没声音；音色与系统那套不同。
- **设置页不能选中文字是设计如此**：拖滑杆/扫卡片时不再误选说明文字（见 8.12），代价是日志、诊断这类内容不能鼠标拖选，要复制请用「关于 → 复制诊断信息」按钮；输入框（能打字的地方）不受影响，`⌘A/⌘C/⌘V` 照常。
- **改动后 5 秒内强杀进程会丢最后一笔**：连续控件（滑杆/取色器/数字框）是「停手 5 秒」或点「保存」才写盘，正常关窗口（`beforeunload`）和切到后台（`visibilitychange`）都会补存一次；但用 `kill -9` / 强制退出这种非正常退出，最后 5 秒内的改动保不住。开关、下拉、录制快捷键这些离散控件是立即写盘的，不受影响（见 8.13）。
- **常规页两栏依赖窗口宽度**：窗口内宽 < 1020px 时自动收成单栏（否则每栏太窄、滑杆顶出卡片）。默认窗口已放大到 1180×800，正常打开就是两栏。
- **场景停用不是删除**：停用的场景（场景库左栏）只是不出现在悬浮球的场景选择 / 菜单栏「切换场景」/ 快捷键循环切换里，也不会被当成当前场景；它的项目、外观、自动启动策略原样留在 `config.json` 里，重新启用一模一样回来。**最后一个启用场景不允许停用**（否则悬浮球无处可去），也不允许把场景删光。彻底删除的入口在场景的**编辑弹窗**里（行内只放 编辑/项目/＋|－ 三个按钮，避免误点）——删除不可撤销，会连带删掉该场景的项目（见 8.15）。
- **提示药丸在极浅的桌面上对比度会降**：它是浅色磨砂胶囊 + 白字，在深色/彩色桌面上最好看（见 8.16 的四背景对照）。如果你的壁纸本身很白、又觉得字发虚，可以把「设置 → 悬浮球 → 提示文字色」改成深色（比如 `#1b2036`）——底色/边框不用动。
- **「隐藏」只藏项目库列表，不碰已经加进场景的项目**：👁 收起来的是左栏（还没加入场景）的条目；右栏「场景已添加」里已有的不受影响，照样显示、照样能用。想让它从场景里消失，请用右栏行内的红色 **×**（见 8.14）。
- **隐藏记录按 id 存**：把项目从项目库彻底移除时，它的隐藏记录会一并清掉；但如果你手动改 `config.json` 里的 `libHidden` 写了不存在的 id，启动时的 `migrate()` 不会替你判定「这项目还在不在」，只是去重和清洗格式 —— 多余的 id 无害，会在你下次隐藏/放回任意项目时随写入一起留下。
- **`bin/imeswitch` 需要随包分发**：已在 `package.json` 里用 `extraResources` 把 `bin/` 打进 `Contents/Resources/bin`。换机器重编：`npm run build:native`（需要 Xcode 命令行工具）。
- **圆点周围有一圈「实心」区域**：收起状态窗口是真机 120×120 的透明方块（圆点 64px + 光晕留白）。为了能接收点击，这一圈不做点击穿透，因此圆点正下方约一圈范围内点击不会落到下层窗口。想要「圆点外完全穿透」，需要回到 `setIgnoreMouseEvents` 方案，但 macOS 上该方案无法可靠转发 hover，会让圆点「看不见但点得着」或反过来，故未采用。
- **`asar` 已关闭**：本项目当前环境对 `.asar` 写入有限制，`package.json` 中 `build.asar: false`。在普通机器上建议改回 `true` 并配合 `asarUnpack` 以缩小体积、加快启动。
- 不收集任何遥测；配置仅存于本地 `~/Library/Application Support/FloatDesk/`。
